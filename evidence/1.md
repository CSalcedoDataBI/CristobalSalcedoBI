## [abios-evidence] Normalization logic — weekend calibration

**What was tested:** The CI-normalization formula matches the observed weekend pattern from the issue
**Evidence from issue:** "25-jul = 16 unique cloners, 26-jul = 14 unique cloners, with ~0 page views" on zero-CI weekend days
**Formula:** `human_clones_count = max(0, clones_count - actions_runs)`
**Test case (Saturday 2026-07-26, 0 CI runs):**
```python
mock_runs.return_value = 0  # weekend, no CI
clones_count = 16
→ human_clones_count = max(0, 16 - 0) = 16  ✓
```

**Test case (weekday with 161 CI runs → 396 clones, matches 17-jul from the issue):**
```python
actions_runs = 161, clones_count = 396
→ human_clones_count = max(0, 396 - 161) = 235
```
The normalized signal separates human installs from CI noise.

## Setup required after merge

The `telemetry-snapshot.yml` workflow requires one secret that the human must create:

**Secret name:** `PORTFOLIO_TELEMETRY_TOKEN`  
**Type:** Classic PAT (or fine-grained) with `public_repo` scope  
**Scope:** Must have access to all 9 tracked repos (they are owned by the same GitHub account)

**How to create:**
1. GitHub → Settings → Developer Settings → Personal access tokens → Tokens (classic)
2. Scope: `public_repo`
3. Copy the token
4. Repo CristobalSalcedoBI → Settings → Secrets → Actions → New repository secret
5. Name: `PORTFOLIO_TELEMETRY_TOKEN`, Value: the PAT

**Pages:** Enable GitHub Pages from `docs/` folder in repo Settings → Pages after the first snapshot run has committed data.
